# Web Push и серверный планировщик

Клиент использует настоящие PushManager + VAPID + Service Worker, сервер — npm web-push в Supabase Edge. In-app уведомления — отдельный inbox, они не считаются доказательством Web Push.

Только явная кнопка запрашивает системное разрешение. Проверяются поддержка, установка на главный экран на iOS и наличие публичного VAPID key. Подписки относятся к конкретному аккаунту/устройству. Есть включение типов, тихие часы 22–09 по умолчанию, IANA timezone, интервалы напоминаний (24/1 по умолчанию), список устройств, выключение и повторная подписка, настоящий серверный тест. Предложения киновечера выключены до согласия, не чаще выбранного интервала и не предлагаются при уже назначенном вечере; напоминание о письмах отдельное и более редкое.

Edge `push-dispatch` допускает только server CRON_SECRET, вызывает `mv_tick`, затем забирает jobs через FOR UPDATE SKIP LOCKED с lease/attempt номером. Очередь имеет уникальность notification/device, серверные dedupe keys, retry/backoff, отключает 404/410 подписки. Service Worker использует стабильный tag и durable квитанцию ID. Web Push по природе не предоставляет транзакционное exactly-once с показом на iOS: при сбое между отправкой и подтверждением возможен транспортный retry, отображение защищено ID/tag. Нельзя гарантировать доставку при Focus, отключённых уведомлениях/сети, системных ограничениях или паузе бесплатного проекта.

Письма становятся видимы только при серверной доставке, а не по локальным часам получателя. Scheduler также создаёт напоминания о событиях; отменённые и устаревшие версии событий отсекаются при выдаче jobs. Все push-тексты общие, без приватных заголовков писем/содержимого.

`setup-scheduler.sql` создаёт минутный pg_cron job, вызывающий Edge через pg_net. URL и CRON_SECRET читаются из Vault, не из публичного SQL. VAPID private key, CRON_SECRET и service_role хранятся только в окружении сервера. Публичный VAPID ключ — Actions variable, не секрет. Генератор не перезаписывает существующие ключи: их замена потребует переподписки устройств.

Проверено: Deno typecheck настоящей функции, SQL-идемпотентность постановки, защищённость dispatcher RPC, UI-запрос разрешения только после кнопки. Реальная доставка Apple на iPhone **ещё не проверена**: требуется production Supabase, deploy Edge, cron и два устройства.
