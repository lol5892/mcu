# Наш Marvel 2.0 — фактический статус

Дата: 9 ноября 2026. Кандидат выпуска по https://lol5892.github.io/mcu/ . Резервные branch/tag v1 сохранены. Исходные каталог, db.ts и model.ts сохранены. Антон отказался от переноса старых отметок; данные автоматически не импортируются и не удаляются.

## Что прошло

- TypeScript и production build.
- 17 unit-тестов: 11 прежних, изоляция облачного кеша/очереди, роли и посезонные оценки, проверка JSON v2.
- 74 SQL-проверки на настоящем PostgreSQL 17: семейные роли, подтверждённый email-контракт, одноразовое приглашение, RLS, чужие/межсемейные UUID, отсутствие прямой записи, версии/CAS, идемпотентность, миграция и отдельное принятие оценок Тани, черновики и скрытие плановых писем, серверная tick-доставка, dedupe уведомлений, read receipts по согласию, личные настройки, Storage policy, форматы/размеры, предложения времени и экспорт без токенов.
- В SQL-тестовом окружении `auth.users`, `auth.uid()` и storage-таблицы воспроизводят контракт Supabase; сама Auth-служба и Storage HTTP API этими тестами не проверяются. Политики и PostgreSQL-функции исполняются реально, а не в JS-моке.
- 7 исходных браузерных сценариев: сохранение v1, две оценки, серии, JSON, защита сброса, фильтры/статистика, пять размеров, офлайн-кеш и новый Service Worker без потери данных.
- 11 новых браузерных **контрактных** сценариев: первое приветствие и серверный флаг/повторный просмотр, два отдельных браузерных контекста и письма, блокировка партнёрской оценки, чат, календарь, сеанс, офлайн-очередь после восстановления сети, конфликт без перезаписи, отсутствие permission prompt до нажатия. Auth/REST в этих сценариях — явно помеченная фикстура, не живой Supabase; они не доказывают Realtime. Дополнительный сценарий проверяет парольный вход, сохранение сессии после перезагрузки, отсутствие plaintext пароля в localStorage, проверку совпадения нового пароля и успешное сохранение без размонтирования формы.
- Deno typecheck обеих Edge Functions; 3 фактических теста обработки JPEG, удаления внедрённого EXIF/GPS и потока с ограничением размера.
- Сборка проверяется на наличие настоящих `sb_secret_` значений, service_role JWT и server-only env markers. Сам префикс SDK `sb_secret_` не является секретом и не вызывает ложного срабатывания.
- Все личные слова приветствия находятся вне публичного репозитория и бандла; UI-тесты/скриншоты используют синтетический текст. Ключи VAPID и scheduler подготовлены вне репозитория, значения не печатались.

## Проверки настоящего Supabase

Проект Free `our-marvel-family`, Frankfurt. Миграции, private Storage, две Edge Functions и минутный cron настроены. Подтверждено реальное получение письма Антоном, его вход и создание семейного пространства. Первый вход настоящей Тани намеренно оставлен для неё.

Временный защищённый Edge runner создал три синтетических Auth-аккаунта без отправки им писем и отдельную тестовую семью. Выполнены 29 проверок с настоящими JWT/REST/Storage/Realtime: третий участник запрещён, чужие данные скрыты; две личные оценки; подмена автора запрещена; идемпотентность; конфликт версий; эпизоды и оценка сезона; чат/редактирование; приватность приветствия и серверный флаг; черновики и плановые письма скрыты, tick доставляет письмо; календарь; совместный сеанс; реальная JPEG-загрузка и атомарное завершение; фото доступны партнёру и недоступны постороннему; VAPID-секреты недоступны клиенту; сообщение доставлено через настоящий Realtime между двумя клиентами.

Изначальные прогоны выявили задержку инициализации Realtime. Подписка теперь явно получает текущий JWT, приложение повторно читает состояние после join и каждые 5 секунд в видимом окне как страховку при восстановлении. Это не гарантирует мгновенную доставку в любых сетевых условиях. Финальный прогон успешно получил настоящий websocket event; polling не выдаётся за этот event.

Один расширенный прогон завершился по тайм-ауту. После добавления ограничений времени HTTP-запросов итоговый прогон завершён успешно. Все временные аккаунты и тестовая семья удалены (проверено SQL). Привилегированный runner заменён HTTP 410, его тестовый код больше не работает на сервере. Личные записи семьи и приветствие настоящей Тани не использовались.

## Что ещё требует двух iPhone

Доставка email Тане и принятие её приглашения, реальные два устройства, установка standalone и показ push на заблокированном экране. Отправитель и очередь работают, но успешный вызов dispatcher без устройств не подтверждает доставку Apple. Проверки этих пунктов описаны в TWO-IPHONES.md. Секреты и ссылки авторизации в отчёт не включаются.

## Ограничения реализации

- Нельзя обещать чаты/фото/плановые отправки без сети. Безопасные изменения ждут активного приложения после восстановления сети. iOS background sync не обещается.
- Снимки не кешируются Service Worker: приватный API не попадает в общий кеш оболочки.
- JSON v2 экспортирует полный доступный архив/метаданные, но пользовательское восстановление намеренно ограничено отсутствующими собственными оценками и своими письмами как черновиками. Общие сообщения/события и файлы не перезаписываются произвольным JSON. Для полного серверного восстановления нужен администраторский backup Supabase.
- Авторское удаление сохраняет общую историю просмотров и данные партнёра; аккаунт/членство остаются. Квитанции идемпотентности не содержат тел писем/сообщений.
- Push-сервис и ОС могут задерживать доставку. Квитанция transport success не доказывает показ на iPhone; стабильные ID/tag предотвращают дубли отображения при большинстве повторов, абсолютное exactly-once через сеть не обещается.
- Бесплатный Supabase может приостанавливать неактивный проект, что влияет на scheduler и своевременность уведомлений.

Запуск: `npm test`, `npm run build`, `npm run test:sql`, `npm run test:edge`, `npm run test:e2e`, `npm run test:family`. Настройка — SETUP.md; ручной сценарий — TWO-IPHONES.md. Финальный выпуск 2.0 до живых проверок не опубликован.


Вход с иконки: изменение пароля подтверждённого синтетического пользователя и повторный вход с новым паролем проверены через настоящий Supabase Auth. Тестовый аккаунт удалён, runner снова отключён (HTTP 410). Редактирование шаблонов почты для этого пути не требуется.

Отдельный браузерный сценарий подтверждает сохранение email-bound приглашения при подтверждении входа в новой вкладке Safari. Ожидающее приглашение хранится локально до семи дней и удаляется после принятия; оно не входит в резервные копии. Авторизация и срок действия проверяются сервером.

## Исправление перехода между браузерами

Подтверждение почты через Gmail/встроенный браузер может потерять локальную ссылку приглашения. mv_join_status возвращает только приглашение для текущего подтверждённого auth.users.email. mv_accept_email_invite повторно проверяет получателя, срок, одноразовость и два места под блокировкой. Неподтверждённые и посторонние аккаунты доступа не получают; роль назначается сервером. UI показывает создание семьи только разрешённому владельцу. Новый браузерный сценарий воспроизводит вход без локальной ссылки и принятие приглашения до приветствия. SQL-проверки охватывают анонимный доступ, чужой UUID, подтверждение email, повтор и старый токен. На действующем сервере выполнена только read-only проверка доступности приглашения получателю; реальное членство и welcome_seen не менялись.
