# Лимиты и план расходов

Проверено по официальным страницам 15.11.2026; тарифы могут измениться. Организация сейчас Free, два активных проекта: исходная семья и новая бета. Создание не потребовало платного тарифа.

## Supabase Free

[Официальный тариф](https://supabase.com/pricing): 500 МБ базы, 1 ГБ файлов, 5 ГБ исходящего и 5 ГБ кешированного трафика, 50 000 MAU, 200 пиковых Realtime-соединений, 2 млн Realtime-сообщений/месяц, 500 000 Edge-вызовов/месяц. Shared CPU и 500 МБ RAM. Автоматические резервные копии не включены, проект может быть приостановлен после недели бездействия. Разрешены два активных Free-проекта. Web Push не требует отдельного Apple Developer account, но расходует Edge, сеть и очередь; гарантированной доставки iOS нет.

10–20 пар — целевой размер закрытой беты, не обещание доказанной производительности. 100 пар / 200 телефонов при одновременном подключении упираются точно в бесплатный максимум Realtime, без запаса. Три подписки приложения мультиплексируются в один WebSocket на клиент, но дополнительные вкладки тоже расходуют соединения. Для уверенной работы 200 одновременно активных клиентов нужен запас и отдельная нагрузочная проверка сетевого тракта.

При 100 парах максимальная занятость по 10 фото до 512+64 КиБ — около 563 МиБ, до накладных/осиротевших объектов; физический Storage Usage проверяется отдельно. Пример трафика, не измеренный прогноз: 1 000 фото × 50 открытий миниатюры × 30 КБ ≈ 1,5 ГБ; 1 000 × 5 открытий полного фото × 400 КБ ≈ 2 ГБ. Плюс API и повторы. Частые просмотры легко превысят Free — лимит количества фото не является лимитом трафика.

Pro начинается с $25/месяц. Если оба текущих проекта останутся активными в той же платной организации на Micro, ориентир — $35/месяц: два compute по $10, минус $10 кредита, плюс базовый $25. Это оценка текущей схемы, не согласие на покупку. Никакой платный план автоматически не подключается. Размещение персональных данных РФ может потребовать иной инфраструктуры и отдельной сметы российского провайдера.

## Статические ресурсы

[Cloudflare Static Assets](https://developers.cloudflare.com/workers/static-assets/): предпочтительное размещение публичной оболочки; статическая раздача не тарифицируется как динамический Worker. [Workers pricing](https://developers.cloudflare.com/workers/platform/pricing/): динамические вызовы Free ограничены 100 000/день; не следует проксировать весь каталог через платную логику без необходимости. Файлы и сборки имеют отдельные ограничения; текущие 245 WebP существенно меньше лимита числа файлов. Домен, если нужен собственный, оплачивается отдельно; он не требуется для *.pages.dev.

[GitHub Pages limits](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits): это не площадка для запуска коммерческого SaaS. Исходная семейная публикация остаётся доступной; публичный сервис с аккаунтами и добровольной поддержкой планируется отдельно. Закрытый технический предпросмотр Sites не заменяет будущую инфраструктуру для реальных пар.

## Контроль

Раз в неделю и до каждого расширения: private beta_admin_report, Supabase Usage (DB, Storage, egress, Realtime, Edge, MAU), ошибки Auth/Storage/Edge, запросы удаления. Отчёт не читает тексты впечатлений и содержимое фото. activity в SQL определяется записанными действиями, не всеми читателями приложения; MAU берётся из Dashboard.

При 70% бюджета — предупреждение владельцу в административном отчёте; при 85% — вручную закрыть создание семей через accepting_families=false, сохранить доступ существующим парам и выяснить причину. Набор также автоматически ограничен 20 семьями. Провайдерский egress не виден из обычного SQL: его нельзя выдавать за измеренный по сумме размеров файлов. До реального запуска требуется настроить уведомления расхода в панели провайдера; отправка владельцу сообщений без его указания не включается.
